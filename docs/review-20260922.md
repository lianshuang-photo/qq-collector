## 发现与修复

| 级别 | 问题 | 修复与验证 |
| --- | --- | --- |
| P1 | 首次运行先打开 data/collector.lock，但 data 目录尚不存在 | 获取锁前创建目录；全新临时目录启动测试先失败，修复后通过 |
| P1 | // 开头的附件 URL 可下载，但其签名未从长期 JSON 清除 | clean 同时处理协议相对 URL；验证长期元数据与消息 JSON 清除签名，待下载队列保留必要 URL |
| P1 | 4009 连接过期错误地丢弃 session/seq | 保留恢复位置；本地 WebSocket 测试验证下一连接使用 Resume 和原序号 |
| P2 | 4900–4913 不可 Resume，旧逻辑仍保留会话 | 清除会话后进入 Identify 路径；逐一测试这些错误码和 4006/4007 |
| P2 | 不允许重试的协议、权限及账号状态错误无限重连 | 记录 blocked、错误码和人工处理标记，停止网关重连；逐一测试九个永久错误码 |
| 发布清理 | 原项目内置实际群标识、原机器路径及不可复验的部署回执 | 移除真实配置和运行断言，改为事件发现群；完善首次安装、LaunchAgent 和隐私边界说明 |

网关语义依据：[QQ 官方 WebSocket 错误码](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/error-trace/websocket.html)及[腾讯 botgo 网关实现](https://github.com/tencent-connect/botgo/blob/master/websocket/client/client.go)。

## 验证

- `uv sync --locked` 成功，Python 3.11.14。
- `python -m unittest -v`：16 项通过，包含多个错误码子测试。
- 新增回归测试均先复现原缺陷，再验证修复。
- `sh -n service.sh` 与 LaunchAgent `plutil -lint` 通过。
- `pip-audit` 检查锁定的 10 个依赖，未发现已知漏洞；这不保证不存在尚未收录的漏洞。
- 上传清单仅包含源码、测试、示例凭证、锁文件、部署模板和文档；不包含虚拟环境、真实凭证、数据库、消息附件、日志或备份。

## 验证边界

这次审查未验证真实 Bot 权限、群接收设置和生产网络。当前仍是单机采集器，跨机器租约、自动主备切换和故障告警尚未实现；离线历史无法保证补齐。测试不能证明零缺陷。

正文按原样保存，传输凭据清理不是通用 PII 脱敏。待下载 URL、SQLite WAL 和历史备份均属于私有数据。部署者需要自行验收采集权限、实际附件下载和长期磁盘容量。
